# Task: Sign-in foundation with Better Auth

## Description

Install Better Auth and wire it to the app's database so later tasks can build on it. This task also proves the library fits: it must work with both database drivers (embedded PGlite and postgres-js for Neon) under Cache Components. If it cannot be made to fit, stop and report rather than work around it.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [x] `better-auth` and `@better-auth/passkey` are added to `package.json` at 1.7.x.
- [x] `src/lib/auth.ts` exports an async `getAuth()` that builds the Better Auth instance once, on first use, from `getDb()` through the Drizzle adapter.
- [x] Email-and-password sign-in is disabled. Google is configured only when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are set.
- [x] Sessions last 90 days and renew on use; the session cookie cache is off.
- [x] Better Auth's `user`, `session`, `account` and `verification` tables are defined in `src/db/schema.ts`, with one generated Drizzle migration committed in `drizzle/`.
- [x] `src/app/api/auth/[...all]/route.ts` serves Better Auth's handler.
- [x] With no environment variables, `npm run dev` starts and `GET /api/auth/ok` (or the library's equivalent health route) answers, using PGlite.
- [x] A script or documented manual check shows a session row can be created and read back on PGlite and on a real Postgres via `DATABASE_URL`.
- [x] `npm run typecheck`, `npm run lint`, `npm run smoke` and `npm run build` pass with no sign-in variables set.

## Technical Details
- New env vars read here: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. In non-production with no secret set, use a fixed development secret; in production a missing secret must throw.
- `getDb()` awaits `connection()` inside Next, so `getAuth()` must be request-time too; never call it at module load.
- Prototype tables are not touched. `src/proxy.ts` currently lets `/api/*` through only with a passcode session when the gate is on; add `/api/auth/` to its exempt list so this route is reachable.
- Files: `package.json`, `package-lock.json`, `src/lib/auth.ts`, `src/db/schema.ts`, `drizzle/*`, `src/app/api/auth/[...all]/route.ts`, `src/proxy.ts` (exempt list only).
