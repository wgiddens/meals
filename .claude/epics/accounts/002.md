# Task: Family rules: invitations, roles and invite-only sign-up

## Description

Add the family model and enforce that only the owner email or an invited email can ever become an account. The rules live in plain functions so they can be checked without a browser.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `user` has a `role` column with values `owner` or `member`.
- [ ] A single-row `family` table holds the family name; an `invitations` table holds name, email (stored lower-case), invited-by, created time and state (`pending`, `accepted`, `cancelled`), with at most one pending invitation per email.
- [ ] One generated Drizzle migration is committed.
- [ ] `src/lib/family.ts` exports `canSignUp(email)`, `inviteMember`, `cancelInvitation`, `removeMember`, `renameFamily` and `listFamily`.
- [ ] `canSignUp` is true only for `OWNER_EMAIL` or an email with a pending invitation, compared case-insensitively.
- [ ] Better Auth's before-user-creation hook refuses creation when `canSignUp` is false or the provider did not verify the email; no user row is written.
- [ ] After creation: the owner email gets role `owner` and the family row is created if missing; an invited email gets role `member` and its invitation becomes `accepted`.
- [ ] `inviteMember`, `cancelInvitation`, `removeMember` and `renameFamily` take the acting member and refuse anyone who is not the owner.
- [ ] `inviteMember` refuses an email that is already a member or already pending, with a clear error.
- [ ] `removeMember` deletes the member's sessions, passkeys, linked accounts and user row; it refuses to remove the owner.

## Technical Details
- `OWNER_EMAIL` is read from the environment. If it is unset in production, `canSignUp` is false for everyone.
- `removeMember` must tolerate the `passkey` table not existing yet in the schema (it arrives in the passkeys task); structure the deletion so that task can add to it, or rely on a foreign key with cascade.
- Keep these functions free of Next.js request APIs so `scripts/check-accounts.ts` can call them against a temporary database.
- Files: `src/db/schema.ts`, `drizzle/*`, `src/lib/family.ts`, `src/lib/auth.ts` (hooks).
