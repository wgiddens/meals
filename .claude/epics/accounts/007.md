# Task: Automated checks for the account rules

## Description

Prove the security rules with a script that CI runs, in the same style as `scripts/smoke.ts`: a temporary embedded database, plain assertions, no network.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `scripts/check-accounts.ts` exists and is run by `npm run smoke` (and so by CI), plus its own `npm run check:accounts`.
- [ ] It proves: an email that is neither the owner nor invited cannot create a user.
- [ ] It proves: the owner email creates the family row and gets role `owner`.
- [ ] It proves: an invited email becomes a `member` and its invitation becomes `accepted`; matching ignores case.
- [ ] It proves: `inviteMember`, `cancelInvitation`, `removeMember` and `renameFamily` refuse a non-owner.
- [ ] It proves: inviting an existing member or an already pending email is refused.
- [ ] It proves: removing a member deletes their sessions, and a lookup of that session then fails; the owner cannot be removed.
- [ ] It proves: once an owner exists, the `OWNER_EMAIL` address cannot create a second owner.
- [ ] It proves: `role` cannot be changed through Better Auth's update-user API.
- [ ] It proves: the dev-owner shortcut is refused when `NODE_ENV` is `production`, using the pure helper from the member gate.
- [ ] The script exits non-zero on any failure and needs no environment variables or secrets.
- [ ] `.github/workflows/ci.yml` needs no new secrets.

## Technical Details
- Follow `scripts/smoke.ts` for creating a temporary PGlite directory (`PGLITE_DATA_DIR`) and applying migrations.
- Exercise user creation through Better Auth's server API or by invoking the same hook functions the library calls, whichever tests the real code path; do not re-implement the rule in the test.
- Passkey removal is not checked here; "Passkeys" runs after this task and adds that assertion.
- Files: `scripts/check-accounts.ts`, `package.json` (scripts).

## Dependencies
- "Member gate": `src/lib/member.ts`, and the completed rules from "Family rules".
