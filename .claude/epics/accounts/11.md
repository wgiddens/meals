# Task: Member gate: replace the household passcode

## Description

Swap the passcode gate for an account session everywhere in one step, so the app is never ungated and never double-gated, then delete the passcode code.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `src/lib/member.ts` exports `currentMember()` (id, name, email, role, or null), `requireMember()` and `requireOwner()`.
- [ ] Every call to `requireHousehold()` in `src/app/actions.ts` is replaced with `requireMember()`; `src/app/api/plate/route.ts` and `src/app/api/import/route.ts` check `requireMember()` themselves and answer 401 when signed out.
- [ ] `src/proxy.ts` redirects signed-out page requests to `/sign-in?next=<path>` and answers 401 for `/api/*`, based on the presence of the Better Auth session cookie. Exempt: `/sign-in`, `/api/auth/*`, `/api/mcp`, `/.well-known/*`, static assets.
- [ ] Not production and no Google client configured: `currentMember()` returns a built-in dev owner, created on first use, and the proxy lets requests through.
- [ ] Production: the dev-owner path is unreachable; the check on `NODE_ENV === "production"` comes before any configuration is read.
- [ ] Production with Google or the secret missing: nothing is accessible, and `/sign-in` can show a not-configured state (the real page comes with "Sign-in page with Google, sign out and My account"; a minimal placeholder page is acceptable here).
- [ ] `/api/mcp` currently lets anyone in when `MCP_API_KEY` is unset. In production it must instead refuse every request when the key is unset, so the assistant endpoint cannot bypass accounts. Local development is unchanged.
- [ ] The decision "is the dev owner allowed?" is a pure function of the environment (for example `devOwnerAllowed(env)`), exported so it can be checked without a Next.js request.
- [ ] `safeReturnPath` is kept (moved to `src/lib/member.ts` or a small module) and treats `/sign-in` as it treated `/login`.
- [ ] `src/lib/household.ts`, `src/app/auth-actions.ts`, `src/app/login/`, `src/components/LoginForm.tsx` and `src/components/SignOutLink.tsx` are deleted, and nothing imports them.
- [ ] `grep -ri "requireHousehold\|isGateEnabled" src scripts` finds nothing.
- [ ] Typecheck, lint, smoke and build pass.

## Technical Details
- `currentMember()` reads the session with Better Auth's server API and the request headers; it is request-time, so callers render it inside `<Suspense>`.
- The layout footer currently renders `SignOutLink`; replace it with plain links to `/family` and `/account`. Both links are added here, before those pages exist, so that the two page tasks never edit `src/app/layout.tsx` and can run in parallel.
- `/api/mcp` keeps its bearer-token check; the only change is refusing requests in production when no key is set.
- Files: `src/lib/member.ts`, `src/proxy.ts`, `src/app/actions.ts`, `src/app/api/plate/route.ts`, `src/app/api/import/route.ts`, `src/app/layout.tsx`, `src/app/api/mcp/route.ts`, `src/app/sign-in/page.tsx` (placeholder), deletions listed above.
- Next's `use cache: private` does not accept `connection()`, and `getAuth()` → `getDb()` awaits `connection()`. Never call `getAuth()` (or anything that reads the session through it) inside a `'use cache: private'` scope; read the session outside it and pass values in. See `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`.
- The dev owner can't be created through Better Auth's normal sign-up, because #10's before-create hook refuses any email that isn't the owner or invited. Insert it directly with Drizzle, or through #10's sign-up completion path, and give it role `owner` (note from #10's implementation).
