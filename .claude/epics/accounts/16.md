# Task: Documentation, deployment setup and production check

## Description

Bring the docs in line with accounts, remove the last traces of the passcode, and write down the manual setup and hand check that only the repo owner can do.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `README.md`, `.env.example` and `docs/ARCHITECTURE.md` describe accounts (sign-in methods, the two-layer gate, family rules, local dev owner, production fail-closed) and list `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and `OWNER_EMAIL`.
- [ ] The "Household passcode gate" section of `docs/ARCHITECTURE.md` is replaced, and the layout listing reflects the new and deleted files.
- [ ] In `docs/PRODUCT.md`, the "Already in the repo (prototype)" bullet about the household passcode is replaced with one line describing accounts, and the accounts entry under "Next" is marked as built.
- [ ] `grep -ri "HOUSEHOLD_PASSCODE\|requireHousehold\|household passcode" .` finds nothing outside `.git/`, `.claude/` and `node_modules/`.
- [ ] Hosted-database wording names Vercel's Neon integration rather than Supabase in `README.md`, `.env.example`, `docs/ARCHITECTURE.md` and the comment in `src/db/index.ts`.
- [ ] A setup checklist in `docs/ARCHITECTURE.md` (or `docs/DEPLOY.md`) covers: creating the Google OAuth client with the callback URL of the fixed proxy URL (production, and the `epic/accounts` preview until the epic merges) plus `localhost`; setting the sign-in variables on Vercel for Production and Preview, including #12's proxy variable; giving Preview its own database, never the production one, because every build runs migrations; removing `HOUSEHOLD_PASSCODE` from Vercel; and that passkeys only work on one domain.
- [ ] A hand-check list is written for production: owner signs in with Google; owner invites a second person; they sign in with Google; each adds a passkey and signs in with it; an uninvited Google account is refused; a removed member is signed out on their next request.
- [ ] Typecheck, lint, smoke and build pass.

## Technical Details
- The Google OAuth client and Vercel variables are created by the repo owner, not by an agent. This task delivers the instructions and records the result of the hand check once it has been done.
- Do not put the owner's real email, client ids or secrets in any committed file; use placeholders.
- When documenting `OWNER_EMAIL`, say it is needed only until the owner first signs in; with it unset in production the owner route is closed but invitations keep working (decided on #10).
- Warn in the docs never to run a local dev server (no Google configured) against the production database: the dev-owner shortcut reuses the existing owner, so anyone who can reach that dev server would act as the owner (decided on #11).
- Vercel Deployment Protection stays on for previews: previews are for the stakeholder to test while signed in to Vercel, and family members use production (stakeholder's decision during #12). Say so in the setup checklist, including that the fixed `epic/accounts` preview Google redirects to is protected too.
- Automatic account linking is off (stakeholder's decision during #12): if a member's Google account is deleted and re-created, sign-in is refused until the owner removes and re-invites them. Say so in the docs, near the family/invitation rules.
- Document the preview-pattern residual (stakeholder's decision on #24): `OAUTH_PROXY_PREVIEW_PATTERN` could match a host in another Vercel scope with a similar slug; exploiting it still needs the Preview proxy secret and exposes at most a preview user's basic Google profile, never a production sign-in.
- Production and previews are fully separate (stakeholder's decision on #24): document two Google OAuth clients (production: its own redirect URI; preview: only the fixed proxy preview's callback), separate secrets, no `OAUTH_PROXY_*` on production, and the long-lived proxy branch (e.g. `auth-proxy`) that must track `main` after the epic merges, including how to keep it up to date.
- Note that the proxy roles key on `VERCEL_ENV`: a production hosted outside Vercel must not set `OAUTH_PROXY_*` (raised in #24's review).
- Status: the stakeholder reported on 2026-11-11 that the Google OAuth clients and Vercel sign-in variables are in place (fully separate setup). The docs should still describe the setup, and the hand check must confirm it works.
- Files: `README.md`, `.env.example`, `docs/ARCHITECTURE.md`, `docs/PRODUCT.md`, `src/db/index.ts` (comment), optionally `docs/DEPLOY.md`.
