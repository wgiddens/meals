# Task: Family page: members, invitations and owner controls

## Description

The page where the owner manages who is in the family and every member can see it.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `/family` shows the family name and lists each member's name, email and role.
- [ ] It lists pending invitations with name and email.
- [ ] The owner sees controls to invite (name and email), cancel an invitation, remove a member and rename the family. A member sees none of them.
- [ ] After inviting, the page shows the app's address to pass on and says the person signs in with Google using that email. No email is sent.
- [ ] Removing a member asks for one confirmation. The owner has no remove control on their own row.
- [ ] Every control posts to a Server Action in `src/app/family/actions.ts` that starts with `requireOwner()` and calls the matching function in `src/lib/family.ts`; a member calling the action directly is refused.
- [ ] Errors from the rules (already a member, already invited, invalid email) are shown next to the form.
- [ ] The page works at 375 px width with tap targets of at least 44 px.
- [ ] Typecheck, lint, smoke and build pass.

## Technical Details
- The app's address comes from `BETTER_AUTH_URL`, falling back to the request's origin.
- Dynamic content sits inside `<Suspense>` with a loading state.
- Files: `src/app/family/page.tsx`, `src/app/family/actions.ts`, `src/app/family/loading.tsx`, small components under `src/components/`.
- Server Actions must be written as `export async function` whose first statement is `await requireMember()` or `await requireOwner()` (`const x = await requireOwner()` is fine). `npm run smoke` scans every `"use server"` file and fails on any other export form (`export const`, `export default`, `export { }`) or on a `"use server"` that isn't the first statement of its file (note from #11).

## Dependencies
- "Member gate": `requireOwner()` and `currentMember()`.
- "Family rules": `src/lib/family.ts`, complete before "Member gate" starts.
