# Task: Sign-in page with Google, sign out and My account

## Description

Give people a way in and a place to manage themselves: the sign-in page with Google, sign out, and a My account page for the display name.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `/sign-in` shows a "Continue with Google" button that starts Better Auth's Google flow and returns to the safe `next` path, or `/`.
- [ ] A Google account that is not the owner or invited lands back on `/sign-in` with "This account hasn't been invited"; no account is created.
- [ ] When sign-in is not configured in production, `/sign-in` says so instead of showing the button.
- [ ] A signed-in visitor to `/sign-in` is sent to `/`.
- [ ] `/account` shows the member's name, email and role, lets them change their display name, and has a Sign out control that ends the session on that device and returns to `/sign-in`.
- [ ] Changing the display name goes through a Server Action that starts with `requireMember()` and validates a non-empty name of at most 80 characters.
- [ ] Both pages work at 375 px width with tap targets of at least 44 px, and signing in requires no typing.
- [ ] Google sign-in works on Vercel preview deployments through Better Auth's `oAuthProxy` plugin: Google redirects to one fixed proxy URL (configured by environment variable, not hard-coded), which returns the user to the preview they started on. Requests on the fixed URL itself are not proxied.
- [ ] Only this project's own origins are trusted for the proxy's return trip (production, `localhost`, and this Vercel project's preview URLs), never all of `*.vercel.app`, so the proxy can't be used as an open redirect.
- [ ] Typecheck, lint, smoke and build pass.

## Technical Details
- Use Better Auth's React client for the Google button in a small client component under `src/components/`.
- `/account` reads the session, so its dynamic part sits inside `<Suspense>` with a loading state, like the existing pages.
- Leave a clearly marked section on `/account` and a slot on `/sign-in` for passkeys; "Passkeys" fills them.
- Preview support was added to this task by the stakeholder's decision (2026-11-10). Read the installed plugin at `node_modules/better-auth/dist/plugins/oauth-proxy/` for how it infers the current URL on Vercel (`VERCEL_URL`) and how `productionURL` is set. Add any new variable to `.env.example`; #16 documents it.
- Files: `src/lib/auth.ts` (plugin and trusted origins), `.env.example`, `src/app/sign-in/page.tsx`, `src/app/account/page.tsx`, `src/app/account/actions.ts`, `src/components/GoogleSignInButton.tsx`, `src/lib/auth-client.ts`.
- Next's `use cache: private` does not accept `connection()`, and `getAuth()` → `getDb()` awaits `connection()`. Never call `getAuth()` (or anything that reads the session through it) inside a `'use cache: private'` scope; read the session outside it and pass values in. See `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`.
- Server Actions must be written as `export async function` whose first statement is `await requireMember()` or `await requireOwner()` (`const x = await requireOwner()` is fine). `npm run smoke` scans every `"use server"` file and fails on any other export form (`export const`, `export default`, `export { }`) or on a `"use server"` that isn't the first statement of its file (note from #11).

## Dependencies
- "Member gate": the member gate and `currentMember()`.
- Hand-testing Google needs an OAuth client; without one, verify the not-configured and dev-owner paths and leave the live check to the documentation and deployment task.
