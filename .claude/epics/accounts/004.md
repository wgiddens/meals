# Task: Sign-in page with Google, sign out and My account

## Description

Give people a way in and a place to manage themselves: the sign-in page with Google, sign out, and a My account page for the display name.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/` as `AGENTS.md` requires, and read Better Auth's installed docs and types rather than relying on memory.

## Acceptance Criteria
- [ ] `/sign-in` shows a "Continue with Google" button that starts Better Auth's Google flow and returns to the safe `next` path, or `/`.
- [ ] A Google account that is not the owner or invited lands back on `/sign-in` with "This account hasn't been invited"; no account is created.
- [ ] When sign-in is not configured in production, `/sign-in` says so instead of showing the button.
- [ ] A signed-in visitor to `/sign-in` is sent to `/`.
- [ ] `/account` shows the member's name, email and role, lets them change their display name, and has a Sign out control that ends the session on that device and returns to `/sign-in`.
- [ ] Changing the display name goes through a Server Action that starts with `requireMember()` and validates a non-empty name of at most 80 characters.
- [ ] Both pages work at 375 px width with tap targets of at least 44 px, and signing in requires no typing.
- [ ] Typecheck, lint, smoke and build pass.

## Technical Details
- Use Better Auth's React client for the Google button in a small client component under `src/components/`.
- `/account` reads the session, so its dynamic part sits inside `<Suspense>` with a loading state, like the existing pages.
- Leave a clearly marked section on `/account` and a slot on `/sign-in` for passkeys; the passkeys task fills them.
- Files: `src/app/sign-in/page.tsx`, `src/app/account/page.tsx`, `src/app/account/actions.ts`, `src/components/GoogleSignInButton.tsx`, `src/lib/auth-client.ts`.

## Dependencies
- Task 3: the member gate and `currentMember()`.
- Hand-testing Google needs an OAuth client; without one, verify the not-configured and dev-owner paths and leave the live check to the documentation and deployment task.
