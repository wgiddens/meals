# Task: One-off account reset script

## Description

Add `scripts/reset-accounts.ts`, the one-off step that moves an environment
to Connect: it deletes every row of `user` in the database `DATABASE_URL`
points at. Sessions, account links and invitations go with them through the
existing `ON DELETE CASCADE`. The `family` row and all meals data stay. The
owner's first sign-in through Connect then recreates them as owner through
the existing `OWNER_EMAIL` bootstrap (the family insert is
`onConflictDoNothing`, so the family keeps its name), and the owner
re-invites members from `/family`.

It is run by the stakeholder, never by an agent, and only after a Neon
snapshot of that database: on Preview in task 005, on Production from the
runbook after the epic merges. The stakeholder chose this reset and
re-invite over migrating account rows (2026-11-11). See the epic's "One-off
reset, run by the owner, after a backup".

## Acceptance Criteria
- [ ] `scripts/reset-accounts.ts` deletes every `user` row in the
      `DATABASE_URL` database, and with it every `session`, `account` and
      `invitations` row. `family` and every meals table are untouched.
- [ ] It refuses to run, before connecting, unless `DATABASE_URL` is set and
      `--confirm-host=<host>` equals the host of `DATABASE_URL`. It never
      falls back to the local PGlite database.
- [ ] It prints only that host, the database name and the row counts
      (before and after), never the URL or any credential.
- [ ] Before deleting, it prints a reminder that `OWNER_EMAIL` must be the
      owner's Google email on this environment, in the deployment that is
      live, or nobody can become owner afterwards.
- [ ] It asks for nothing interactively and exits non-zero on any refusal or
      error.
- [ ] It is not part of `npm run smoke` and has no npm script that runs it.
      The command to run it is given in its header comment, for task 004 to
      copy into `docs/DEPLOY.md`.
- [ ] A small offline check, run by `npm run smoke`, proves it refuses a
      mismatched `--confirm-host` and a missing `DATABASE_URL`, and connects
      to nothing when it does. A check that it deletes the right rows, against
      a throwaway local database, is welcome but not required.

## Technical Details
- Files: `scripts/reset-accounts.ts` (new), `scripts/check-reset.ts` (new,
  or another new file for the check), and `package.json`'s `scripts` block
  only (a `check:reset` entry and adding it to `smoke`).
- Keep the host guard a pure function the check can call, and run the
  refusal paths in a child process with `DATABASE_URL` pointing at a host
  that can't be reached, so a missed guard fails the check rather than
  touching a database.
- `getDb()` falls back to PGlite when `DATABASE_URL` is unset; check
  `DATABASE_URL` before calling it.
- Task 001 edits `package.json`'s dependencies; stay inside the `scripts`
  block so the two merge cleanly.
