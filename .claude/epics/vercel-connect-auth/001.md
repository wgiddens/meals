# Task: Google sign-in through Vercel Connect, OAuth proxy removed

## Description

Replace Better Auth's built-in Google provider with Vercel Connect's Better
Auth adapter, under the same provider id `google`, in every environment, and
remove the OAuth proxy in the same change, so the app is never on two Google
paths at once. Better Auth's base URL comes from the request's host,
limited to this deployment's own addresses. The gate fails closed in
production whenever Better Auth couldn't start. Every check runs offline,
with no Vercel, Connect or Google secret.

This is the epic's "Implementation Strategy" step 1. Its design is the
epic's "Architecture Decisions" (all except the sessions and the reset
script, which are tasks 002 and 003). The spike branch
`claude/spike-vercel-connect` (commits `efb960f`, `57fc2d4`) is reference
for the wiring only: it ran Connect beside the old provider as
`google-connect` on Preview only, which this task does not.

Before writing code, read the relevant guide in `node_modules/next/dist/docs/`
as `AGENTS.md` requires, and read the installed `better-auth` (dynamic
`baseURL`, `genericOAuth`, `account.encryptOAuthTokens`, `onAPIError`) and
`@vercel/connect` (`betterauth` entry, `ConnectError`) sources rather than
docs or memory.

## Acceptance Criteria

Provider:
- [ ] `@vercel/connect` is a dependency, pinned to an exact version (2.9.1,
      or the latest when the task starts); its `betterauth` source was
      re-read first.
- [ ] Google sign-in is `genericOAuth({ config: [connect({ providerId:
      "google", connector })] })`, with `connector` from
      `VERCEL_CONNECT_GOOGLE`. No built-in `google` social provider is
      configured, and `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` are not
      read anywhere.
- [ ] `googleConfig()` becomes a check for the connector (or is replaced by
      one); its callers are updated.
- [ ] The Google button still calls `authClient.signIn.social({ provider:
      "google" })`; the callback is `/api/auth/callback/google`.
- [ ] `account.encryptOAuthTokens: true`.

Base URL and origins:
- [ ] `authAllowedHosts(env)` in `src/lib/gate.ts` is a pure function of the
      environment, never the request, and returns exactly the epic's table:
      production (`VERCEL_ENV=production`) the hosts of `BETTER_AUTH_URL`
      and `VERCEL_PROJECT_PRODUCTION_URL`; preview `VERCEL_URL` and
      `VERCEL_BRANCH_URL`; and, only when `NODE_ENV` is not `production`,
      also `localhost:*` and `127.0.0.1:*`. Never a preview host in
      production, never a wildcard such as `*.vercel.app`.
- [ ] Better Auth's `baseURL` is `{ allowedHosts: authAllowedHosts(env),
      protocol }`, with `protocol` `"https"` when `VERCEL_ENV` is
      `production` or `preview`, otherwise `"auto"`. `baseURL.fallback` is
      not set; `advanced.trustedProxyHeaders` stays off.
- [ ] Confirmed (and noted in the PR) that `vercel env pull` writes
      `VERCEL_ENV="development"`, and that `localhost` sign-in therefore gets
      `"auto"`.
- [ ] `trustedOrigins()` keeps today's rules, minus the proxy origin.

Gate:
- [ ] When `NODE_ENV` is `production`, `gateMode()` is `sign-in` only if
      `VERCEL_CONNECT_GOOGLE` and `BETTER_AUTH_SECRET` are set and
      `authAllowedHosts(env)` is non-empty; otherwise `closed`. This covers
      production with `BETTER_AUTH_URL` unset or invalid, and a
      `NODE_ENV=production` run outside Vercel.
- [ ] Outside production with no connector, the gate is the dev owner, as
      today: `npm run dev` on a fresh clone and CI need nothing.

Proxy removed:
- [ ] Gone: `oAuthProxy`, `oauthProxyRole()`, `oauthProxyOrigin()`,
      `oauthProxySecret()`, `previewOriginPattern()`,
      `proxyDestinationAllowed()`, the three guard plugins, and the proxy's
      flow checks in `scripts/check-auth.ts`.
- [ ] `grep -ri "oauth_proxy\|oAuthProxy\|GOOGLE_CLIENT_SECRET" src scripts`
      finds nothing.

Errors:
- [ ] `onAPIError.onError` logs a `ConnectError`'s `code`, `status` and
      `statusText` only, never `vendor`; `errorURL` stays `/sign-in`.
- [ ] `/sign-in?error=oauth_code_verification_failed` shows a fixed,
      generic message. `GoogleSignInButton.tsx`'s comment no longer mentions
      the proxy; its behaviour is unchanged.

Offline checks (`scripts/check-auth.ts`, `scripts/check-accounts.ts`,
`scripts/smoke.ts`), with `connect({ getVercelOidcToken })` given a fixed
fake token, `fetch` stubbed for `connect.vercel.com/oauth/token` and
`/oauth/userinfo`, and no network used:
- [ ] **Authorize step:** sign-in started on each allowed host goes to
      `https://connect.vercel.com/oauth/authorize` with `client_id` = the
      connector, PKCE, and `redirect_uri` =
      `https://<that host>/api/auth/callback/google`.
- [ ] **Token request:** carries `Authorization: Basic <connector>:<oidc>`,
      the `code_verifier`, and the same `redirect_uri`.
- [ ] **Through the adapter's own profile mapping** (full sign-ins, not the
      mapping called directly): `email_verified` false, missing or the
      string `"true"` gives `EMAIL_NOT_VERIFIED`; an uninvited verified
      email gives `NOT_INVITED`; an existing member's email with a different
      `sub` gives `account_not_linked`; an invited verified email becomes a
      Member, and its stored `account` tokens are encrypted (not the
      plaintext the stub returned).
- [ ] **Hosts:** a request on a host outside the allowlist is refused.
      Production's allowlist never contains a preview host or a wildcard, and
      is empty, so the gate is `closed`, when `BETTER_AUTH_URL` is unset or
      invalid.
- [ ] **ID-token sign-in** is refused, and no built-in `google` social
      provider is configured.
- [ ] **Hand-back paths:** `/api/auth/callback/google/oauth-proxy` and
      `/api/auth/oauth-proxy-callback` answer 404, in every environment's
      configuration.
- [ ] **Gate table** (`scripts/smoke.ts`, `scripts/check-accounts.ts`)
      covers the new variable: production with no connector, no secret or no
      allowed host is `closed`; local with no connector is the dev owner;
      rows include `VERCEL_ENV=development`.
- [ ] The existing rules still hold and are still checked: the invite-only
      before-create hook, the verified-email requirement,
      `disableImplicitLinking`, server-only `role`, the after-create hook,
      cookie cache off, `getAuth()` request-time.

## Technical Details

- Files: `package.json`, `package-lock.json` (dependency only),
  `src/lib/auth.ts`, `src/lib/gate.ts`, `src/app/sign-in/page.tsx`,
  `src/components/GoogleSignInButton.tsx`, `scripts/check-auth.ts`,
  `scripts/check-accounts.ts`, `scripts/smoke.ts`, and callers of
  `googleConfig()` if any outside these.
- `src/lib/gate.ts` is imported by `src/proxy.ts`; keep
  `authAllowedHosts()` free of Node-only and Better Auth imports.
- Leave session lifetime (`SESSION_MAX_AGE_SECONDS`, 90 days today) to task
  002, and docs, README and `.env.example` to task 004.
- Better Auth throws at start-up when `allowedHosts` is empty; the gate rule
  above is what keeps production from serving a broken instance.
- If the installed `better-auth` or `@vercel/connect` behaves differently
  from the epic (for example, the callback path or how `protocol` applies
  to loopback hosts), stop and ask rather than adapt the design.
