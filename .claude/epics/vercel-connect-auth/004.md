# Task: Docs, Connect setup and the production runbook

## Description

Bring the docs in line with Google sign-in through Vercel Connect, before
anyone runs the preview hand check (task 005) or the production
switch-over. The heart of it is a runbook in `docs/DEPLOY.md`: the
stakeholder's setup and reset steps for Preview and Production, with
backup and rollback, in the order the epic sets. Merging the epic deploys
production at once, so the runbook makes clear which production steps come
before the merge.

The epic is the source for every step: "Infrastructure", "Implementation
Strategy" steps 4 and 5, "Rollback", "Risks" and "Task 5's hand check".
Write what the code from tasks 001–003 actually does; where it differs
from the epic, ask rather than paper over it.

## Acceptance Criteria

`docs/DEPLOY.md`:
- [ ] **No proxy:** the fixed preview / OAuth proxy setup, the
      `OAUTH_PROXY_*` rows, the `auth-proxy` instructions and the "Known
      residual (previews only)" section are gone. No `oauth_proxy` or
      `oAuthProxy` anywhere in it, and `GOOGLE_CLIENT_SECRET` appears only
      in the rollback steps.
- [ ] **The separation table** shows Production and Preview each with their
      own Google client and connector (Preview and Development share the
      spike's `meals-connect-spike` client and `google/meals-google-spike`
      connector), their own `BETTER_AUTH_SECRET` and database; `BETTER_AUTH_URL`
      on Production only.
- [ ] **Connect setup:** OIDC federation (Team issuer); a Google OAuth
      client whose only redirect URI is `https://connect.vercel.com/callback`;
      a connector linked to the right environments only (project links);
      `VERCEL_CONNECT_GOOGLE` per environment. Placeholders only, no real ids
      or emails.
- [ ] **Connector-replacement warning:** don't replace a connector once
      members have signed in through it unless task 005 showed `sub` is
      Google's own; otherwise a replaced connector means another reset.
- [ ] **Variables:** what each environment keeps (Production:
      `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `OWNER_EMAIL`,
      `VERCEL_CONNECT_GOOGLE`), and what is deleted at the end
      (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OAUTH_PROXY_URL`,
      `OAUTH_PROXY_SECRET`, `OAUTH_PROXY_PREVIEW_PATTERN`, Preview's
      `BETTER_AUTH_URL`, the spike branch's override).
- [ ] **Preview steps** (task 005 runs them): snapshot the Preview database;
      set Preview's `VERCEL_CONNECT_GOOGLE` and check Preview's
      `OWNER_EMAIL`; run the reset (the exact command from task 003, with
      `--confirm-host`); run the hand check on the epic branch's preview, on
      its branch address and its per-deployment address.
- [ ] **Production runbook**, numbered as the epic's step 5, with steps 1–5
      marked as required before the epic merges: (1) production Google
      client and connector, linked to Production only; (2) Production's
      `VERCEL_CONNECT_GOOGLE`; (3) `OWNER_EMAIL` set on Production and the
      live deployment built after it; (4) project-link isolation: a code
      exchange from the epic branch's preview against the production
      connector gets a 403; (5) Neon snapshot of the production database;
      (6) merge, production deploys; (7) run the reset on Production; (8)
      the owner signs in, re-invites everyone and runs the production hand
      check; (9) delete the old variables and Google clients.
- [ ] **Rollback,** as the epic's "Rollback": before step 9, Instant
      Rollback plus copying back only `user`, `session`, `account`,
      `invitations` and `verification` from a Neon branch of the snapshot
      (not a full restore, which loses meals data), or a second reset if
      `sub` is Google's own; after step 9, recreate `GOOGLE_CLIENT_ID` and
      `GOOGLE_CLIENT_SECRET` for that environment first.
- [ ] **Hand check** section rewritten for Connect: the app's rules (owner,
      invited member, uninvited refused, removed member signed out) on
      production and on a preview's branch and per-deployment addresses,
      plus the Connect items task 005 checks, with a "Result" section to
      fill in (date, who, outcome, token-request count from the connector's
      Observability tab; no real emails).
