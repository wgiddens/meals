# Task: Production pre-merge setup (runbook steps 1–5)

## Description

Merging the epic deploys production at once. Without a connector the gate
is `closed` and the family, existing sessions included, is locked out. So
the production runbook's steps 1–5 in `docs/DEPLOY.md` (written in task
004) are done before the epic merges. Making them a task means the epic PR
can't open until they are done (stakeholder, 2026-11-11). The switch-over
itself, runbook steps 6–9 (merge, reset, re-invite, delete the old
variables and clients), stays outside the epic and follows the merge.

The stakeholder does the setup in Google Cloud, Vercel and Neon; the dev
chat guides them through the runbook, reads what it can through the Vercel
tools, and runs or guides the isolation check. See the epic's
"Implementation Strategy" step 5.

## Acceptance Criteria
- [ ] **1.** A production Google OAuth client exists whose only redirect
      URI is `https://connect.vercel.com/callback`, and a production
      connector uses it, linked to Production only.
- [ ] **2.** Production's `VERCEL_CONNECT_GOOGLE` is the production
      connector. (The live, pre-epic code ignores it.)
- [ ] **3.** `OWNER_EMAIL` is set on Production, and the live production
      deployment was built after it was set.
- [ ] **4.** Project links are isolated: a code exchange from the epic
      branch's preview against the production connector gets a 403
      (`Connector is not enabled for this environment`).
- [ ] **5.** A Neon snapshot of the production database is taken, and its
      name and time are recorded.
- [ ] Production's `BETTER_AUTH_URL` and `BETTER_AUTH_SECRET` are still
      set, so the merged code's gate will be `sign-in`.
- [ ] `docs/DEPLOY.md` "Production pre-merge result" records the date, who did each step and the
      outcome. No real emails, ids or secrets.
- [ ] If any step fails or can't be done, stop and ask the stakeholder: the
      epic does not merge.

## Technical Details
- Files: `docs/DEPLOY.md` (results only). No code changes.
- If step 4 needs a request crafted by hand against `connect.vercel.com`,
  use the epic branch's preview and the Preview environment's own OIDC
  token, never a production credential, and never paste a token into the
  chat, PR or files.
- Old Google clients and variables are not touched here; they are runbook
  step 9, after the merge.

## Dependencies
- Task 005: Preview passed its hand check, so the code being merged is
  known to work.
- The stakeholder, for Google Cloud, Vercel and Neon.
